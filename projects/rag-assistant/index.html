AI-Powered Multimodal Conversational Assistant

A modular Streamlit application that combines document retrieval, OCR, PDF parsing, web search, a 7B language model, and optional image generation in one conversational workflow.

Problem

Useful answers often depend on information outside the model

A standalone language model cannot reliably answer questions about a user’s uploaded documents, text embedded in images, or newly retrieved web content. The project addresses this by collecting multiple input types and converting them into context that can be retrieved before response generation.

The main engineering objective was integration: combining document processing, semantic retrieval, multimodal input handling, response generation, and a practical web interface without tightly coupling every component.

System Workflow

From raw input to retrieved context and final response

01

Input collection

The Streamlit interface accepts chat questions, PDF files, images, and optional web-search requests.

02

Parsing and OCR

PDF text is extracted directly, while EasyOCR converts text inside uploaded images into searchable content.

03

Embedding and retrieval

Sentence-transformer embeddings are indexed with FAISS so the most relevant passages can be selected for each query.

04

Response generation

The retrieved context is combined with the user prompt and passed to Zephyr-7B to produce the final answer.

Pipeline

A retrieval-first response architecture

User Query→PDF / Image / Web→Parsing + OCR→Embeddings→FAISS Retrieval→Zephyr-7B

Retrieval does not guarantee factual correctness by itself, but it provides the model with relevant external context instead of relying only on its internal parameters.

Input Types

Different sources share one retrieval workflow

PDF documents

Uploaded files are parsed and converted into text that can be chunked, embedded, and searched.

Images with text

EasyOCR extracts text from JPG and PNG inputs before the same retrieval process is applied.

Web-enriched queries

External search results can supplement local context when the question requires current or broader information.

Image-generation requests

Creative image prompts can be routed to Stable Diffusion XL as a separate generation capability.

Engineering Decisions

Why the system was built as a modular prototype

Separating the interface, parsing, retrieval, and generation layers makes experimentation easier. FAISS could later be replaced with a hosted vector database, the embedding model could be upgraded, or the response model could be changed without redesigning the whole application.

The application also exposes the selected context before answering, which is useful during development because it makes retrieval behaviour easier to inspect.

Limitations

Integration is complete; formal evaluation remains future work

Retrieval quality

No fixed benchmark currently measures whether the retrieved passages are consistently the most relevant ones.

Response grounding

The model can still produce unsupported statements, so retrieved context and generated answers should be reviewed critically.

OCR variability

Text extraction quality depends on image resolution, contrast, layout, and font characteristics.

Runtime cost

Using a 7B model together with OCR, retrieval, and image generation creates significant memory and latency requirements.
