Humanoid Agent Harness

A configurable virtual robot environment that connects the hosted OAX-1B-Humanoid model to structured observations, JSON tool calls and deterministic Controller validation for goal-directed find, pick and place tasks.

Problem

Language-model output is useful, but it cannot be trusted as execution authority

An LLM can interpret flexible natural-language goals, but it can also select the wrong tool, refer to the wrong object or request an action before its preconditions are satisfied. Directly applying those outputs to a robot or environment would make state transitions unpredictable.

The harness therefore separates high-level language reasoning from deterministic execution. OAX-1B proposes a structured action; a state-aware Controller decides what the environment is actually allowed to execute.

Agent Loop

A small, explicit and inspectable control architecture

01

Goal classification

The user request is interpreted as find-only, find-and-pick or pick-and-place.

02

Structured observation

The model receives agent position, inventory, target state, reachability and the available tool list.

03

Hosted OAX-1B inference

The current observation is sent to the OAX-1B-Humanoid model through a Hugging Face Space API.

04

Controller validation or repair

The Controller checks action order, arguments, inventory and reachability before choosing the executable action.

05

World state update

Only the Controller-approved action changes the agent position, inventory or goal-completion state.

The model receives observation data but cannot directly modify the world. State changes are owned by the Controller and environment layers.

Action Contract

A deliberately constrained tool vocabulary

The hosted model proposes one of six high-level actions. Keeping the vocabulary compact makes validation transparent and prevents the language model from bypassing the intended control flow.

get_visible_objects get_robot_status search_object pick_object place_object stop

search_object, pick_object and place_object are only valid when the current world state satisfies the relevant preconditions.

Limitations

An inspectable harness rather than a physics simulator

Grid-based environment

The current world does not model physics, collisions, perception uncertainty or continuous robot motion.

Hosted inference latency

The Hugging Face Space currently runs on CPU and can introduce cold-start and runtime delays.

Constrained task set

The Controller intentionally supports a small set of tools and task patterns to keep validation deterministic and easy to inspect.

Physical deployment requirements

Returning the harness to the real humanoid robot would require perception validation, motion planning, collision checks and hardware-level safety controls.

Outcome

A complete agent loop with deterministic execution boundaries

The project demonstrates how a custom language model can interact with an environment through structured tools while remaining constrained by a separate execution layer.

The result is a lightweight platform for inspecting model decisions, Controller repairs and world-state transitions without requiring access to the physical humanoid robot.
